# 公開範囲・利用条件の計画

作成・更新日：2026-10-21（JST）  
計画書バージョン：0.1.2  
状態：コードはMIT License、著作権表示はCopyright (c) 2026 Eisuke Kagawaに決定。公開範囲・時期は以下の計画に従って整備します。Gitタグ作成とGitHubへの公開は未実施です。

査読開始に向けて、実際に用いた研究コードを先行公開し、読者向け推論サンプルとモデル重みを段階的に追加する方針を提案します。ViTの学習本体は元のnotebook形式を維持します。新しい推論サンプルの完成や全モデルの再訓練を、研究コードの先行公開の必須条件にはしません。

## 1. 最初に公開する範囲

| 対象 | 初期公開での扱い | 説明 |
|---|---|---|
| `training/` | 含める | SSL、3-class、2-classの学習コード。元のnotebookと起動条件を保持し、個人パスは一般化する |
| `evaluation/original/` | 含めることを推奨 | 論文で使用した予測・評価・アンサンブル処理を査読者が確認できる。識別子らしい使用例は一般的な画像名へ置換する |
| `human_test/`のソース | 含めることを推奨 | 課題準備、割付、試験実施の手順を示す。実際の回答・参加者名・割付データは含めない |
| `ek_schedule_exe.py` | 含める | 今回提供された元の時刻待機モジュール。配置とimport方法を説明する |
| README、`docs/`、照合ツール、Git設定 | 含める | 使用コードの所在、実行環境の確認状況、原本からの変更、公開範囲を説明する |
| 保存済み学習指標CSV・学習曲線PNG | 内容点検済みのものを含める | 患者画像や参加者記録と区別する。今回の学習ログ・学習曲線が対象 |
| `src/`、`examples/`等の案内README | 準備状況を示す場合に含める | 実装待ちであることを明記する。動作する推論パッケージとして案内しない |
| 患者ECG、患者対応表、実際のhuman-test回答 | 含めない | 公開コードとは別に管理する。データ提供の可否・条件は研究上の承認範囲を確認して論文に記載する |
| モデル重み、実行結果、ローカルバックアップ | 初期公開には含めない | 重みは実物確認後に別配布する。`.cache/`や更新用バックアップをZIP等へ混入させない |

学習コードだけに範囲を絞ることもできます。ただし今回は評価・human-testの元ソースも整理済みのため、研究手順の確認に役立つ範囲として同時公開を推奨します。human-testの実施コードは、回答データを解析して論文の統計結果を生成するコードと同一ではありません。論文の全解析を再現できると説明する段階では、実際の統計解析コードと図表生成コードの所在も確認します。

## 2. 査読用初期公開までの順序

1. 実施済みの識別子・個人パスの一般化について、公開用変更記録と変更前後のハッシュを確認する。元の私的な開発コードは保持する。
2. 同梱済みの`ek_schedule_exe.py`と、Linux/WSL・Colabでのリポジトリ配置・import方法を確認する。パスの一般化とモジュール同梱の完了は、学習全体の実行検証とは区別する。
3. 3モデルそれぞれについて、選択したcheckpoint、epoch、実際の選択基準、選択に用いたデータの役割、学習ファイル・セル・起動コマンド、初期化元checkpointを記録する。SSL→FT3→FT2の対応も示す。選択基準は著者の確認に基づき「training lossとvalidation lossを確認し、過学習の兆候がないと判断したepochのうち、validation lossが最も低いepochのcheckpointを選択した。」と記載します。使用した指標はtraining lossとvalidation lossです。具体的なvalidationの分割、採用checkpoint・epoch、通常重み／SWAの区別は実記録と対応付けます。自動early stoppingや、testデータを選択に使用していないことは、この説明から推定しません。記載項目と確認方法は[checkpoint選択の記録](checkpoint_selection.md)にまとめます。
4. 確認できる開発環境・依存ライブラリを記録する。元の環境記録がない版番号は推測で固定せず、別途動作確認した環境と区別する。
5. 決定済みのMIT Licenseと著作権表示を[LICENSE](../LICENSE)で示す。第三者由来のコードに必要な著作権表示・ライセンス・NOTICEが保持されているか確認する。
6. 公開するGitのファイル一覧を確認する。患者・参加者情報、重み、認証情報、バックアップが入っていないことを確認してから初回公開する。`.gitignore`の存在だけで確認完了とはしない。
7. 初期公開のコミットを固定し、実際のリポジトリURLとタグまたはコミットを論文のCode availabilityに記載する。初期公開タグの候補は`v0.1.0`とする。

READMEの文書バージョン`0.1.3`は説明文書の改訂番号です。上記の`v0.1.0`は今後作成する公開版タグの提案で、現時点の公開済みリリースを示しません。査読中にコードを修正する場合も、初期公開タグは保持し、変更履歴を追加します。

## 4. 決定したコードのライセンス

ユーザーの指定に基づき、**コードはMIT License**とし、著作権表示は**Copyright (c) 2026 Eisuke Kagawa**とします。正式な条件はリポジトリ直下の[LICENSE](../LICENSE)を参照してください。

## 5. 重み・データの利用条件

コードのライセンスを決めても、患者データやモデル重みの配布条件が自動的に決まるわけではありません。

- **モデル重み**：実際に配布する資産の由来、初期重みの条件、公開権限を確認し、重み用の利用条件とモデル説明を決める。今回の計画ではまだライセンスを付与しない。
- **患者ECG・参加者データ**：このリポジトリには含めない。提供できる場合に限り、窓口・条件・必要な手続きを論文へ記載する。未確認の段階で「合理的な請求に応じて提供する」と約束しない。
- **論文・図表**：コードのライセンスとは別に扱う。公開する説明資料に転載物がある場合は、その利用条件を確認する。

## 6. 論文・READMEで明示する内容

現時点の公開範囲に合わせ、次の情報を揃えます。

- 研究で使用した学習・評価・試験実施コードのうち、どこまで公開したか。
- 個人パスと識別子を一般化したこと、元の形式を保持したこと、公開用変更の記録先。
- 実行確認済みの範囲と、Linux/WSL/Colabでの検証がまだ必要な範囲。
- モデル重み、読者向けサンプル、患者・参加者データの提供状況。
- 実際のリポジトリURL、公開版のタグまたはコミット、利用条件。

Circulationを含むAHA誌では、資料・情報の利用可能性に制限がある場合、投稿時に開示するよう案内されています。論文のCode/Data availabilityとリポジトリの説明を一致させます。この計画だけで個別の投稿要件が満たされたとは判断しません。[AHA Data Sharing](https://www.ahajournals.org/data-sharing)

## 7. 公開前に残る確認事項

1. **論文の最終checkpointとの対応**：選択基準は上記のとおり確認済みです。選択したファイルとepoch、具体的なvalidation分割、通常重み／SWAの区別、起点の実行と初期化元checkpointを記録する。確認できない項目は確認中と表示する。
2. **第三者由来部分の表示**：コードやモデルの由来を確認し、必要なライセンス・著作権・NOTICEを保持する。
3. **公開範囲と論文の記載**：実際に公開するファイル、動作確認範囲、モデル重み・データの提供状況を揃える。公開後に実URLとタグまたはコミットを記載する。

コードのライセンスと著作権表示は上記のとおり決定済みです。公開範囲は「元の研究ソース＋必要な補助モジュール＋説明文書」を提案します。GitHubへの公開操作はまだ行っていません。
